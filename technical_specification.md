# Техническое задание — ClinicBook

## 1. Описание проекта

ClinicBook — веб-приложение для онлайн-записи на приём в частную клинику. Позволяет пациентам выбирать врача и слот, администраторам — управлять расписанием, врачам — видеть загрузку. Цель — убрать телефонные звонки из процесса записи и снизить число неявок.

## 2. Целевая аудитория

- **Пациенты** — запись, просмотр и отмена визитов.
- **Администраторы** — управление расписанием и записями.
- **Врачи** — просмотр своего расписания.

## 3. Функциональные требования

### 3.1. Аутентификация и роли

- Регистрация и вход по email/паролю.
- JWT-аутентификация.
- Роли: `patient`, `admin`, `doctor`.
- Разграничение доступа: пациент видит только свои данные, админ — все, врач — своё расписание.

### 3.2. Онлайн-запись на приём

- Пошаговый выбор: специальность → врач → дата → слот.
- Отображение только свободных слотов (генерируются из расписания врача).
- Проверка пересечения с другими записями пациента.
- Создание записи со статусом `confirmed`.
- Экран подтверждения с деталями визита.

### 3.3. Личный кабинет пациента

- Раздел «Мои визиты»: предстоящие и прошедшие.
- Отмена записи (не позднее чем за 2 часа до визита).
- История визитов со статусами `completed`, `cancelled`.

### 3.4. Панель администратора

- Просмотр расписания всех врачей на выбранную дату.
- Управление записями: перенос, отмена.
- Просмотр статуса доставки email-напоминаний.

### 3.5. Уведомления

- Email-напоминание за 24 часа до визита.
- Email-подтверждение сразу после записи.
- Email-уведомление при отмене или переносе.

## 5. Описание обработки ошибок

| Ситуация | UX-решение |
|---|---|
| Ошибка валидации формы записи | Подсветка поля, текст ошибки под полем, кнопка неактивна |
| Нет свободных слотов | Заглушка «Нет свободных слотов» + кнопка «Выбрать другого врача» |
| Слот занят в момент подтверждения | Сообщение «Слот уже занят» + автообновление списка |
| Пересечение с другой записью пациента | Предупреждение «У вас уже есть запись на это время» |
| Отмена менее чем за 2 часа | Модальное окно «Позвоните в клинику для отмены» |
| Отсутствие данных | Заглушка «Записей пока нет» + CTA «Записаться» |
| Сетевая ошибка | Тост «Не удалось загрузить. Проверьте соединение» + кнопка «Повторить» |
| Неавторизованный доступ | Редирект на страницу входа с сообщением «Требуется авторизация» |
| Недостаточно прав | Сообщение «У вас нет доступа к этому разделу» |
| Недоставка email | Логирование + уведомление администратора в панели |

## 6. Модель данных

### User
- `id` UUID
- `email` string (unique)
- `password_hash` string
- `role` enum(patient, admin, doctor)
- `full_name` string
- `phone` string (optional)

### Doctor
- `id` UUID
- `user_id` UUID (FK)
- `speciality` string
- `bio` text

### ScheduleSlot
- `id` UUID
- `doctor_id` UUID (FK)
- `start_at` timestamp
- `end_at` timestamp
- `is_booked` boolean

### Appointment
- `id` UUID
- `patient_id` UUID (FK)
- `doctor_id` UUID (FK)
- `slot_id` UUID (FK)
- `status` enum(confirmed, cancelled, completed)
- `created_at` timestamp
- `updated_at` timestamp

### Notification
- `id` UUID
- `appointment_id` UUID (FK)
- `type` enum(confirmation, reminder, cancellation)
- `sent_at` timestamp
- `status` enum(sent, failed)

## 7. API Endpoints

| Метод | Путь | Описание | Доступ |
|---|---|---|---|
| POST | /api/auth/register | Регистрация | Все |
| POST | /api/auth/login | Вход | Все |
| GET | /api/doctors | Список врачей и специальностей | Patient |
| GET | /api/doctors/:id/slots | Свободные слоты врача | Patient |
| POST | /api/appointments | Создать запись | Patient |
| GET | /api/appointments/my | Мои визиты | Patient |
| PATCH | /api/appointments/:id/cancel | Отменить запись | Patient, Admin |
| GET | /api/admin/schedule | Расписание врачей | Admin |
| PATCH | /api/admin/appointments/:id | Перенести/отменить | Admin |
| GET | /api/doctor/schedule | Своё расписание | Doctor |

## 8. Технологический стек

- Frontend: React, TypeScript, Tailwind CSS, Vite
- Backend: Node.js, Express, TypeScript
- БД: PostgreSQL, Prisma ORM
- Аутентификация: JWT, bcrypt
- Email: Nodemailer + SMTP
- Инфраструктура: Docker, Docker Compose
- Тестирование: Jest, Supertest, React Testing Library

## 9. План разработки MVP

1. Настройка проекта, БД, Docker.
2. Аутентификация и роли.
3. CRUD врачей и слотов (админ).
4. Запись пациента (пошаговый флоу).
5. Личный кабинет и отмена.
6. Панель администратора.
7. Email-уведомления.
8. UI по концепции Minimalist.
9. Тесты и деплой.
