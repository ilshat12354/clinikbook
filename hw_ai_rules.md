# hw_ai_rules.md — Описание проекта и стека

## 1. Проект

**Название:** Tickets API.  
**Назначение:** внутренний REST API для регистрации, просмотра и обработки заявок отдела технической поддержки.  
**Пользователи:** сотрудники компании.  
**Данные:** заявки могут содержать ФИО, контакты, описание инцидентов — потенциально персональные данные и коммерческая тайна.

## 2. Технологический стек

| Компонент | Технология |
|---|---|
| Язык | Python 3.11 |
| Web-фреймворк | FastAPI |
| ORM | SQLAlchemy 2.0 |
| БД | SQLite |
| Валидация | Pydantic v2 |
| Тесты | Pytest, httpx |
| Линтеры | ruff, black, mypy |
| Контейнеризация | Docker, docker-compose |
| ASGI-сервер | uvicorn |
| AI-агент | Cline + Ollama + Qwen2.5-Coder 7B |

## 3. Ключевые требования к стилю и архитектуре

- Чистая слоистая архитектура: `routers` → `services` → `repositories` → `models`.
- Строгая типизация: все функции и методы имеют type hints.
- Pydantic-схемы отделены от ORM-моделей.
- Никакого «магического» кода и глобального состояния.
- Понятные имена на английском, docstring на русском.
- Покрытие тестами ключевых сценариев.
- Безопасность: локальная обработка данных, без передачи кода во внешние облака.
- Соответствие 152-ФЗ и внутренней политике ИБ.

## 4. Требования к AI-агенту

- Работать только в пределах текущего репозитория.
- Не изменять файлы без явного запроса.
- Соблюдать стиль проекта.
- Предлагать решения, совместимые с SQLite и FastAPI.
- Не использовать устаревшие библиотеки и deprecated API.
